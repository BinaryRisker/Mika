Ask the user to approve the next matching step before you do it. Sending a message and deleting need this unless that chat is already allowlisted: set action to send or delete, target to the name in the title bar (or what will be deleted), content to the exact text, and amount to an empty string. Placing an order or booking, or another final step on a page that shows the amount to pay, also needs it: give the amount shown on screen. An order, submit, or other request with no digits in the amount is rejected. A plain submit on a page with no amount to pay is done directly, without this call. Fill everything in first, then call it, then do the step as your very next action on that screen: tapping elsewhere, swiping, going back or opening another app or page in between, or waiting more than 3 steps, cancels the approval. One approval is used up by the next matching step even if that step fails; ask again for the next one. The target must be visible on screen, as shown there. A send, delete, or spending step without approval is refused with confirmation_required. If nobody is here, a send or delete is not run and the result says it was not sent or not deleted; do not ask. Payment itself is not confirmed here: use hand_to_user with reason payment. If the user declines, do not try the step again; report the current state and end.
