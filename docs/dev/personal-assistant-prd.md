本文只定个人用法层和扩展格式。主循环、虚拟屏、浏览器、沙箱、电脑连接、记忆的三类（事实、偏好、做法）都不重做。目标是市面上最能办事的个人助理，同时让 Mika 上游的更新还能合并进来。强在已经登录的 App 上把事情做完、问人的那一句人能看见、难撤销的动作有规矩。实现放在分支 `personal-assistant`，见第 16 节。OpenMinis 和 Operit 的对照在调研文档第 4.6 节。

## 1. 要解决的问题

Mika 已经能在后台把一件事办完。它还不是一个个人助理，因为五件事没有产品形状：

- 人不在旁边时，只有花钱会停。发送、发帖、删除会做完。定时任务和电脑交来的任务问不到人，这些动作也不会停。
- 到点执行的结果散落在各自的对话里。打开 App 看见的是空对话或上一次聊天，不是今天。
- 日程和闹钟只能往系统里写，不能读回来。早晨要知道「今天有什么」就得去翻某个 App。
- 个人技能只是一段 Markdown。带脚本的做法必须打进 APK。外部接口已经能走 MCP，但没有一个可导入的包把知识、技能、脚本和一条默认关闭的常规放在一起。
- 它不会在了解这个人之后，自己去外面找值得看的东西。人不说关注什么，它就不该搜；人说过，也只在有新的、对得上的来源时才出声。

成功时，用户工作日早上打开 Mika，看见今天的安排、有没有等他点头的动作、以及夜里那些常规是无变化、做成了还是失败了。他没有新说一句话。一条他自己启用的常规可以在沙箱里处理文件，不能绕过发送前的确认。他若启用了「值得看」，今天这一页上会多一条带来源、对得上他写下的关注的建议；没有新东西时那一行是无变化。建议留在 Mika 里。夜里常规若问了他一句，他打开时看得到问题和选项；回答之后是一次新的运行，不会把昨夜的屏幕接着点下去。

## 2. 谁在用，哪几天算成了

一个用户，一台已经配对好手机操作的 Android 手机，模型密钥是他自己的。他会把重复的事交给定时任务，也会从别的 App 把文字或图片分享进来。他不在屏幕前时，Mika 仍可能到点运行。

下面这些日子做成，这一版就可以停。没做成的日子说明还缺哪一条需求。

| 日子 | 做成的样子 |
| --- | --- |
| 早晨 | 工作日到点读系统日历和下一个闹钟。和上次记下的一样就不通知，今天这一页写「无变化」。有会议变动或没有下一个闹钟，就通知一条 |
| 夜里 | 免打扰时段内不跑模型任务。固定提醒仍到点响。任务连着失败只通知一次，直到成功或用户打开 |
| 发消息 | 发给允许名单外的对象会出确认卡。用户不在、定时任务、电脑交来的任务：留稿，不发出。允许名单里的对象直接发 |
| 分享 | 从别的 App 分享文字或图片，选一条已有常规后才开始。不选就不跑 |
| 换机 | 导出一个加密文件，在另一台 Mika 上导入记忆、技能、包、常规和名单。服务商密钥不在文件里 |
| 发现 | 他确认过要关注的题目，并启用「值得看」。有一条新的、带来源、对得上某个关注的内容时通知一次。同一链接下次不再通知。没有关注，或这次没有新的，就不通知。建议留在 Mika 里，不发到别的 App |
| 问一句 | 人不在时常规发出的问题，会出现在原对话和通知里，带上选项。这次运行不等待。他以后回答，同一条对话开始一次新运行。进程被杀后问题还在，虚拟屏不从中断处继续 |

## 4. 原则

这些原则来自调研里各家同时在做的部分，并收成 Mika 能执行的句子。

1. **难撤销的动作由执行入口决定。** 技能、提示词、包都不能写「这次不用问」。
2. **问不到人就不做外部动作。** 留稿或拒绝，并在结果里写明。不把动作推迟到下次有人时自动发出。
3. **没变化就不出声。** 常规可以跑，通知只在结果变了或需要人的时候发。
4. **打开 App 先看见今天。** 对话仍是办事的地方。
5. **扩展不进入主循环。** 新做法是包。新接口是用户启用的 MCP。新的只读设备能力随应用版本加，不由包声明权限。
6. **人点头之后才启用会自己跑的东西。** 常规模板、导入的技能、学来的草稿，都是先关着或先待确认。
7. **先有用户确认过的关注，才向外找。** 没有关注就不搜索、不通知。找到的东西带来源，对不上就不说。建议留在本机对话里。

## 5. 这一版不做什么

- 不建云同步、云电脑、连接器商店、代用令牌。
- 不加人设、形象、心情、多助手会议。
- 不把 GPL 项目的代码并进来。
- 不增加即时通讯渠道，不把微信的 `confirms` 改成真。
- 不新增任务系统、目标操作系统、向量记忆。
- 不让包注册工具、改审批、读其他应用的私有目录。
- 不把通知监听默认打开。
- 不从被杀死的屏幕中间接着跑。
- 不把「自主」改成无人值守也可以付款或发送。
- 不从屏幕文字、通知或其他 App 推断兴趣。关注只来自用户保存的名单，以及他已经能改的记忆。
- 不做一条会自己发帖的 Feed。调研结果不发到微信或其他 App。
- 不因为要调研，就把整组网页工具交给无人值守的运行。`WebGroup` 里的打开、点按、上传、执行脚本不在这趟运行里。
- 不把每个工具改成默认先问。Operit 的默认询问会让能做的事也停下来。
- 不在 App 里嵌 MNN 或 llama.cpp，不把沙箱从 Alpine 换成 Ubuntu。模型继续走现有服务商配置。
- 不做跨设备同步运行时。电脑继续把任务交给这台手机并取回结果。
- 不把 OpenMinis（GPL-3.0）、Operit（LGPL-3.0）、Operit2（AGPL-3.0）的代码并进来。MinisSkills 不整份搬入。别人的技能缺了工具就失败。
- 不把同时运行的对话数提高到 Android 14 以下也能并行。不从被杀死的屏幕中间接着跑。

## 6. 规矩

规矩是一份存在本机的配置，每个任务开工时读一次，装进这次运行。正在跑的任务沿用开工时的那份。改配置管之后的任务。

### 6.1 动作分类

沿用现在的不可逆判定，把对外动作分成三类。判定仍看模型手里的那一屏，不另加一套词表。

| 类 | 包含 | 人在场 | 人不在场 |
| --- | --- | --- | --- |
| 付款 | 现在会拦的付款和下单（`IrrevAction.pay`、`IrrevAction.order`，以及带应付金额的提交） | 询问模式下出卡；判定为付款的那一下仍 `hand_to_user`。自主模式下不拦，与现在相同 | 拒绝，说明没做成 |
| 送达 | `IrrevAction.send`：发送、发布、发表、转发、回复 | 不在允许名单上就出卡，自主模式也一样。同意只放行紧接着的那一个匹配动作 | 不执行。对话里留下对象、正文和「没有发出」 |
| 删除 | `IrrevAction.delete` | 出卡，自主模式也一样。同意只放行这一下 | 不执行，说明没删 |

允许名单的一项是：包名或网站的可注册域名，加上一个对象名（会话标题、邮箱或「自己」）。对象名对不上当前屏幕上的对象，就当成不在名单里。名单为空表示全部要问。

按包名的禁止是：这个包不许送达、不许删除、不许付款，三项可单独关。禁止优先于允许名单，也优先于自主模式。命中以后直接拒绝，不出卡。

同一动作只进一档。`ClassifiedRisk` 已经把「屏上有应付金额的删除或提交」标成付款；这种仍走付款档，不另出一张删除卡。`IrrevAction.submit` 在没有应付金额时这一版不改，避免把保存笔记也问一遍。笔记、闹钟、文件夹和沙箱里的文件不走这三档。

### 6.2 确认卡

复用现在花钱那张卡的路径：对话、悬浮胶囊、通知都能回答，回答只对这一下有效。卡片写明 App 或网站、动作种类、对象、正文摘要。用户拒绝或关掉，这一下不做，任务继续，模型被告知被拒绝。

人不在场时不出卡，也不把卡留到下次打开再自动执行。打开 App 之后，留稿出现在原对话里，用户可以改完再说「发出」。那是一次新的、人在场的动作，重新过规矩。

电脑经 CLI / MCP 交来的任务、定时任务、条件任务、渠道任务，都算人不在场。子任务保持只读，到不了这三档。

### 6.3 花费

两个上限，都是用户填的整数 Token，0 表示不限制。默认 0。

- 本地日历日的总上限，含主循环和旁路调用。
- 每条常规自己的上限，只计这次运行。

到达上限时，这一次运行停在当前步骤，结果写明停在花费上，不开始新的模型调用。记账仍用现有的 `UsageLedger`，不另估一份。例行常规在用户没有单独指定模型时用轻量模型；轻量模型不会调用工具时，这次常规改用主模型，并在结果里写一句。

创建第一条会调用模型的常规时，若总上限仍是 0，计划页问一次要不要设每天上限。跳过就保持 0。

### 6.4 安静与失败

免打扰是本地时间的一个闭区间，默认关。用户打开后，建议填 22:00–08:00，由他确认。

- 固定提醒在区间内仍送达。
- 会调用模型的计划若落在区间内，不启动。下次允许的时刻再跑一次，同一窗口不跑两次。错过的次数记在计划上，和现在的间隔计划一样。
- 条件检查同样推迟。推迟期间不把「没检查」记成条件失败。

同一计划连续失败时，第一次失败通知，之后折叠，直到一次成功或用户打开该对话。折叠的次数写在今天这一页上。模型出错、步数用完、花费停、规矩拒绝，都算这次没做成。用户取消不算失败。

创建或修改时间时，界面写出接下来三次的本地时间。第 4 条路线图里的时区缺口仍在：改时区后，要到下一次认领才重算。这一版不顺手修它，预览按保存当时的时区算。

## 7. 只读来源

两个工具，风险为只读，失败时给出原因，不改任何数据。

**日程。** 读本机日历里今天和明天的事件：标题、开始、结束、是否全天、地点、日历名。读不到权限时返回「未授权」，并给出去系统设置打开的说明。不读取受邀人的邮箱名单，避免把通讯录整份送进模型。

**下一个闹钟。** 读系统报告的下一个闹钟时刻和标签。没有则明确返回没有。设闹钟的现有工具不变。

通知摘要不在前三个阶段。做的时候：用户逐个包名打开；只读标题和正文；像验证码、密码、卡号的文本丢弃，连「有一条被丢弃」都不进模型；默认全关。这一版的早晨常规不依赖它。

## 8. 常规

一条常规是用户拥有的记录，不是模型临时创建的隐藏计划。

| 字段 | 含义 |
| --- | --- |
| 名字 | 用户看得见的短名 |
| 目标 | 到点或被点选时交给运行的那句话。用户原话，不经模型改写后覆盖 |
| 技能 | 可空。有则运行开始时列入技能索引，模型仍用 `skill_read` 自己读 |
| 何时 | 手动、分享、到点、条件。到点和条件复用 `schedule_task` 的规则 |
| 规矩 | 引用第 6 节的全局规矩，可额外指定这条常规的允许名单和花费上限 |
| 停止 | 分钟数。到点还未结束就停，并写出已做的事。步数沿用任务运行里的现有上限 |
| 出声 | `变化才通知` 或 `每次都通知`。默认前者 |
| 启用 | 关着的常规不登记闹钟 |

模型可以提议一条常规，提议出现在对话里，用户保存后才存在。保存时默认关着，除非用户在同一张卡上打开启用。到点登记走现有的 `TriggerEngine`，不要求模型调用 `schedule_task`。`schedule_task` 仍只在对话里发起的运行中提供。

内置第一条，安装后不自动启用：

- 名字：早晨安排
- 何时：用户本地时间的工作日早上，默认 8:00，他可以改
- 目标：读今天和明天的日程、下一个闹钟。和上次记下的日程集合、下一次闹钟时刻都相同，就回答「无变化」并带上今天的日期。有变化就列出变化
- 工具：这次运行只给这两个只读工具和回答。不装配手机操作、网页、沙箱，因此它打不开 App，也发不出消息
- 出声：变化才通知
- 停止：10 分钟

上次记下的值存在这条常规上，不进记忆。第一次跑只记下，不通知，除非读失败或没有下一个闹钟。

内置第二条，安装后同样不自动启用。它和早晨安排用同一套「按这一次运行收窄工具表」，名单不同。阶段 C 先把收窄做成；阶段 F 只换名单，不另做第二套。

- 名字：值得看
- 何时：用户本地时间的工作日，默认 12:30，他可以改
- 关注：若干条短句，存在这条常规上，用户增删。空着就不能打开启用。启用中若被清空，下次不搜索，回答「还没有关注」，不通知，并把常规关回。
- 目标：先读关注名单，以及这次运行能读到的事实和偏好。核对标准沿用 `info-research`：找到原始出处，写上时间，只有一处来源就标明，同一篇通稿的转载不算第二个来源。技能入口写的是 `web_navigate` 和到 App 里站内搜；这趟运行没有这些工具，改用 `web_search` 和 `web_read_page` 做同一件事，缺工具就停在这一步。查询词只用关注里的题目，加上年份、语言这类限定。每条建议对得上名单上的某一句原文，并给出这次用 `web_read_page` 读过的网址和页面上的日期，页面没有日期就写「页面上没有日期」。已经分享过的网址，或已经分享过的同一主张，不再说。没有新的就回答「无变化」，并带上今天的日期。最多三条。建议只写可以接着做的一步
- 技能：`info-research`。运行开始时列入技能索引，模型仍用 `skill_read` 自己读。技能正文不能把下面的工具表撑开
- 工具：`web_search`、`web_read_page`、`memory_search`，加上回答。不给 `memory_save`、`memory_edit`、手机操作、沙箱，也不给 `web_navigate`、点按、上传、执行脚本。今天网页能力整组折叠（`WebCapability.folds`，`WebGroup`），所以这张名单是执行入口收窄的，不是写在提示词里
- 搜索：沿用用户已经配置的端点。没配置时这次没做成，不改用浏览器；`web_search` 失败结果里那句「改用浏览器」在这趟运行里不生效。查询若包含记忆里的邮箱或电话，而这串字符不在关注原文里，拒绝这一次搜索并把原因写进结果。不把整段记忆或对话放进查询
- 读页：没有打开页面读到正文的条目不写进建议。`web_read_page` 不可用时，这次没做成，不用搜索摘要顶上
- 出声：变化才通知
- 停止：15 分钟
- 已分享：存在这条常规上，保留最近 200 条网址和对应主张。更早的可以再出现
- 不要这类：用户在那条建议上点。应用写入一条偏好，来源是这次点击，不是模型调用 `memory_save`。下次运行先读到它
- 没人看：从通知发出到下一次运行开始，这段对话没有被打开，算这一次没人看。点「不要这类」或打开对话都算看过。连续两次没人看，常规暂停，今天这一页写「因为没人看，先停了」，不再登记下一次。用户打开那次对话，或重新启用，之后继续

模型可以在人正在看的对话里提议一条关注。卡片写明依据的是哪一条已有记忆；没有可引用的记忆时，卡片改成问要关注什么，同一条对话里被关掉之后不再问。用户保存才写入名单。保存不自动启用，除非他在同一张卡上打开启用。助手经工具新建或修改的常规，在用户保存之前不存在，也不做两分钟后自动留下的半份。

另有一条模板，不预填网址，用户填完并保存才成为常规，保存时仍是关的：

- 名字：盯这个页面
- 用户填：一个 http(s) 网址，加上要等的变化。变化是出现某段文字、数字跨过他写下的线，或正文和上次不同
- 工具：与「值得看」同一张名单
- 第一次只把读到的摘要记在这条常规上，不通知。之后和上次不同，才通知一条
- 失败沿用第 6.4 节的折叠。到点间隔不变，不另做一套越失败等越久的调度

分享类常规：何时 = 分享，并记下接受的类型（文字、图片，可多选）。用户从系统分享面板进来，若有匹配的常规，先列出名字，选一条才把分享内容放进目标并开始。没有匹配或用户取消，行为与现在相同：进草稿，不自动开跑。

常用说法是启用中的手动常规，显示在空对话和新对话输入框上方，点一下把目标填进输入框，不直接发送。

删除常规时，它登记的计划一起删。已经跑出的对话留下。

## 9. 今天这一页

侧栏第一项。打开 App 时，若没有一条正在看的对话从通知点进来，就落在这一页。

页上只有这些，空的就写空，不填建议文案：

- 下一个日程、下一个闹钟。读失败时写原因。
- 等你处理：还没回答的确认、留稿。点进去是那次对话。
- 今天的常规：每条一行，状态是还没到、无变化、做成、没做成、推迟到安静时段结束。点一行打开原对话。「值得看」有新建议时，这一行带上关注原文和来源的域名。它暂停时写「因为没人看，先停了」。不另开一块帖子列表。
- 失败折叠：哪条计划叠了几次，直到成功或被打开。

这一页不开始运行，不新建对话。立即执行仍走计划页或该行上的一个按钮，按钮沿用计划页已有的「立即执行」。

阶段 G 把没答上的 `ask_user` 放进「等你处理」。阶段 C 不验收这一句。

## 10. 扩展包

一个包是一个目录，导入后放在应用私有存储里。

```text
pack-id/
  manifest.json
  knowledge/     # 可选，APP.md 或 SITE.md，格式见 knowledge-format.md
  skills/        # 可选，每份一个目录，SKILL.md
  scripts/       # 可选，manifest.json 与脚本，规则见 skill-scripts.md
  routines/      # 可选，常规模板，启用前不是常规
```

`manifest.json` 只含：`id`、`version`、显示名、一句说明。不接受权限列表、网络开关、令牌、工具注册。脚本要联网时，仍看脚本清单里的 `network`，以及设置里已有的「允许脚本联网」。两者都开才跑，否则拒绝并说明。

导入时：

- 技能过现在的 `SkillDrafter.validate`。内置技能的名字不能占。
- 脚本路径、解释器、`needs` 过现在的清单规则。解释器仍只有 python3、node、sh。
- 校验失败则整份不装。
- 装上之后技能为试用，常规模板为关。卸载去掉这份包的技能、脚本和还没启用的模板；已经启用的常规问用户是停用还是留下。留下的常规不再引用已卸的脚本，到点若脚本缺失就失败并说明。
- 更新先显示技能正文和模板的差异，用户确认才替换。试用状态不因更新自动变成正式。

运行脚本时，`run_bundled_script` 增加一种来源：`pack:<id>`。脚本在该对话的沙箱里跑，默认断网，工作区仍是这个对话的。包不能把文件写到沙箱外；要给用户的文件继续走现有的「下载/Mika」。

包里的知识只在这份包启用技能被读到、或任务进入它写的那个 App 时，按现在的知识补给规则附上。不在开局塞进全文。

这一版不做包的公开市场。导入来自用户选择的本地文件或一段分享来的目录压缩包。压缩包只接受清单里列出的相对路径，拒绝绝对路径和 `..`。

第一份随应用给出的示例包只有「列表收成表格」：技能说明如何用现有的逐屏采集得到行，脚本把行写成 CSV 放到工作区，再由现有导出进「下载/Mika」。它用来验证包的路径，不新增采集工具。

## 11. 轻账与导出

轻账每条是：时间、对话编号、常规编号（可空）、用户目标的原文、结局一句话、产出文件名列表。不存屏幕文字、不存工具参数里的输入内容。保留 400 天，和用量账本同一量级。运行记录清理不删轻账。

搜索从今天这一页进入，只搜这三样：目标原文、结局那句话、文件名。结果点进对话；对话已删除则只显示轻账上的字。

导出文件用用户设置的口令加密，口令不保存。里面有记忆、画像、个人技能、包、常规、允许名单和禁止名单、轻账。关注名单、已分享的网址和主张在常规上，随常规走。「不要这类」在记忆里，随记忆走。没有服务商密钥、没有 MCP 令牌、没有锁屏 PIN。导入到另一台时先校验版本，技能和包按第 10 节再校验一遍，常规全部以关闭状态写入，名单覆盖前先给用户看数量。

## 12. 分阶段

每一阶段可以单独合并。后一阶段不开始，前一阶段的验收仍成立。

### 阶段 A：规矩

需求：第 6.1、6.2 节。

验收：

- 询问模式下，人在场，`IrrevAction.send` 且对象不在允许名单：出卡；同意只覆盖下一动；拒绝后该动作没有执行。
- 同一发送在定时任务里：不出卡，对话里有留稿，动作没有执行。
- 电脑交来的任务同样留稿，并且仍然不能付款。
- 自主模式、人在场：付款和下单仍像现在这样不拦；不在允许名单上的发送仍出卡；禁止名单命中的发送直接拒绝，不出卡。
- 允许名单的对象名与屏幕标题栏上的对象不一致：出卡。`ConfirmationGate` 今天就是只认标题栏里的发送对象。
- 精确「提交」且屏上没有应付金额：仍直接做，不因为这一版变成出卡。
- 子任务仍然只读，到不了发送和删除。

### 阶段 B：安静、失败、花费

需求：第 6.3、6.4 节。

验收：

- 免打扰内的模型计划不启动，区间结束后的下一次窗口只跑一次。固定提醒在区间内送达。
- 连续三次失败只有第一条通知；第四次成功后，下一次失败会再通知。
- 编辑时间时能看见接下来三次。
- 总上限耗尽后，下一次模型调用不发出。常规上限只停下那一条。
- 上限为 0 时行为与现在相同。

### 阶段 C：来源、早晨、今天

需求：第 7、8、9 节里除分享、常用说法、「值得看」和「盯这个页面」以外的部分。阶段 C 把「按这一次运行收窄工具表」做成，早晨安排是它的第一张名单。

验收：

- 授权之后，日程工具返回的标题和时间与系统日历一致；未授权时不返回事件正文。
- 早晨常规第一次只记账。第二次无变化无通知。把一项会议改到另一时刻后，再跑一次早晨安排，有一条通知，今天这一页能点进该对话。这次运行的工具表里没有手机操作、网页和沙箱。
- 打开 App 默认是今天这一页。从通知点进来则是那条对话。
- 常规关着时不设闹钟。

### 阶段 D：分享与常用说法

需求：第 8 节剩余部分。

验收：

- 分享图片且存在一条匹配常规：先看到名字，选定后才开始。取消后草稿还在，任务没有开始。
- 没有匹配常规：与现在一样，不自动开始。
- 手动常规出现在空对话上方，点一下只填字，不发送。

### 阶段 E：包、轻账、导出

需求：第 10、11 节。

验收：

- 一份含非法工具名或 `..` 路径的包整份不装。
- 示例包能在沙箱里写出 CSV，并出现在「下载/Mika」。联网脚本在总开关关闭时拒绝。
- 卸包后，未启用模板消失；用户选择留下的常规在脚本缺失时失败，不执行包外命令。
- 搜索能按文件名找到 30 次运行记录已经清掉之后的那次产出。
- 导出文件用错误口令打不开。正确口令导入后，常规是关的，本机服务商密钥还在、没有被文件覆盖。

### 阶段 F：值得看

需求：第 8 节的「值得看」「盯这个页面」，以及第 9 节里关于这一行怎么显示的那一句。依赖阶段 B 的花费和免打扰、阶段 C 的今天这一页和工具表收窄。不放宽阶段 A：这趟运行本身不装配能发送的工具。

验收：

- 关注为空时不能启用。运行时名单已经是空的：不调用 `web_search`，不通知，回答里有「还没有关注」，常规回到关闭。
- 用户写入一条关注并启用。搜索和读页返回一个新网址：通知一条；结果里有这条关注的原文和该网址；今天这一页能点进这次对话。
- 同一网址再跑一次：不通知，结果是无变化。同一主张换一个转载网址，也不通知。
- 用户点「不要这类」后再跑：被这条偏好挡掉的内容不再出现。写入的是应用，不是这趟运行里的 `memory_save`。
- 这趟运行的工具表里没有手机操作、沙箱、`memory_save`、`memory_edit`、`web_navigate`、点按、上传、执行脚本。
- 没配置 `web_search`：这次没做成，没有打开浏览器。
- 记忆里有一串关注原文中没有的邮箱。这次发出的 `web_search` 查询里出现这串邮箱时，该次调用被拒绝，原因在结果里。
- 免打扰时段内不启动。花费上限沿用第 6.3 节，上限为 0 时不因此多拦一遭。
- 运行结束后没有执行过 `IrrevAction.send`。结果文本不在别的 App 里。
- 连续两次通知在下一次运行前都没被打开：常规暂停，页上写「因为没人看，先停了」，不再登记下一次。打开那次对话或重新启用后，下一次窗口会再跑。
- 对话里关掉关注提议：名单不变，常规仍关。用户在同一张卡上保存并打开启用之后，常规才登记。
- 「盯这个页面」第一次只记账。正文变化后的下一次有一条通知。工具表与「值得看」相同。

### 阶段 G：问句留得住

需求：无人在场时的 `ask_user` 仍立刻结束等待，但问题和选项要送到人手里。可以单独合并，不依赖阶段 A 到 F，也不放宽它们。

验收：

- 定时任务里调用 `ask_user`：运行不等待；原对话里看得到问题和选项；有一条通知；工具结果仍是 `no_answer`。这一条不新增发送拦截，发送和删除仍只由阶段 A 的第 6 节决定。
- 人在场时的 `ask_user` 仍按现在的 `inputTimeoutMs` 等待，选项仍是 2–8 个。
- 进程在等人回答时被杀：重启后问题还在对话里。今天这一页若已有，问题在「等你处理」。回答之后，同一条对话开始一次新运行。上一次的虚拟屏不恢复。
- 工具结果是 `no_answer`，里面没有替用户填上的选项。阶段 A 合并之后，紧接着的发送、付款、删除仍走第 6 节。阶段 G 单独合并时不改发送规矩，只保证问题已送达、结果里没有假答案。

通知摘要已按第 7 节那四句做：用户逐个包名打开；只读标题和正文；像验证码、密码、卡号的文本丢掉，连「有一条被丢弃」都不进模型；默认全关。

## 13. 风险

| 风险 | 处理 |
| --- | --- |
| 不可逆判定漏掉某种「发送」 | 漏掉的后果是没问就发出。阶段 A 的验收先覆盖微信文件传输助手以外的一个会话，以及浏览器里的一封邮件草稿。判定补漏沿用现在的词表维护方式，不在包里打补丁 |
| 留稿被用户当成已经发出 | 留稿的那一轮固定带「没有发出」，今天这一页把它放在「等你处理」 |
| 日历权限被系统收回 | 工具返回未授权，早晨常规记为没做成，按失败折叠通知 |
| 包里的脚本很慢或写很多文件 | 沿用沙箱的超时和工作区配额。常规的分钟数到了就停 |
| 用户把允许名单填成一个含糊的姓 | 对象名必须与屏幕上的对象一致才放行，对不上就问 |
| 花费上限把一次正在付款前的购物任务停掉 | 停的时候写出停在花费上。已经进确认卡的那一下，若卡已弹出，等用户答完再停后续调用 |
| 「值得看」把搜索摘要当成已经读过 | 没经 `web_read_page` 读到正文的条目不进入建议。读页不可用则整次没做成 |
| 查询词带上记忆里的联系方式 | 关注原文里没有的邮箱或电话，拒绝该次 `web_search`。不靠技能正文答应「我会注意」 |
| 同一篇通稿换几个网址反复通知 | 已分享记录里同时有网址和主张。主张相同就不再通知 |
| 用户没看，仍每天响 | 连续两次没打开就暂停，页上写明原因 |
| 无人在场的问题被模型当成可以自己选 | `no_answer` 之后的发送、付款、删除仍走第 6 节。问题正文要送达，避免用户不知道被问过 |
